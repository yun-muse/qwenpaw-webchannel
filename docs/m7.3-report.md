# M7.3 report — end-to-end heartbeat against silent tunnel death

Mechanism and the code-level proof: `docs/m7.3-findings.md`. Scope per the
milestone brief: give the plugin a liveness signal the relay edge cannot fake,
prove it against a blackhole relay, keep every M7.1/M7.2 guarantee, and keep
relay-cf and relay-node in lockstep.

## Changes

- `plugin/relay_client.py`
  - The app-level `{"t":"ping"}` loop is replaced by the `hb` beat. The
    constructor keeps the `ping_interval` / `pong_timeout` names (existing
    callers and tests pass them) and adds `hb_max_missed=2`; defaults are now
    15 s / 10 s. `ping_interval=None` (or `<= 0`) disables the beat.
  - Each beat sends `{"t":"hb","id":"hb-<n>"}` through `_send_direct`
    (bypassing the send queue) and waits `pong_timeout` for the matching
    `hb_ack`. Success: `missed=0`, sleep `ping_interval`. Timeout: `missed +=
    1`, file-log event `hb_miss` (`id`, `missed`), retry after 2 s, and at
    `hb_max_missed` consecutive misses close the socket — an ordinary phase
    end, so the run loop reconnects with backoff. A send failure records the
    close code (`_note_close_code`) and closes.
  - Reader: `hb_ack` is consumed before dispatch; only an ack whose `id`
    matches the outstanding beat sets the event. `hb_ack` never reaches
    `on_frame`. The existing `ping` / `pong` branches are untouched.
  - Counter, missed count and outstanding id reset on every connect.
  - WS-level `ping_interval` / `ping_timeout`, `send_timeout`, the
    `asyncio.wait(FIRST_COMPLETED)` phase race, `_cancel_phase_tasks`, the
    supervisor, `_tx_lock`, close-4000 fatality and generation gating are all
    unchanged.
- `relay-cf/src/index.ts` — after envelope validation and before the
  rate-limit bucket, `hb` is answered by the DO with `hb_ack` (id echoed when
  it is a string) and returns: no token spent, nothing forwarded, no
  `agentLastSeen` stamp. An `hb` from a socket that is not `this.agent` is
  dropped silently (parked/superseded generations must not learn that they are
  alive). The `ping` branch and the stamping rule are untouched; the
  `agentLastSeenAt` comment now names `hb` as non-stamping too.
- `relay-node/server.js` (lockstep) — `handleAgent` acks `hb` for the slot
  holder (silent drop for parked sockets) right after the `ping` branch;
  `handleClient` drops an `hb` from a client so it is never forwarded to the
  agent (relay-cf drops it by the same rule).
- `protocol/frames.md` — `hb` / `hb_ack` rows in §2.1/§2.2, a note on why
  `ping` cannot detect this death (edge auto-answer) and what `hb` guarantees
  (never forwarded, never stamps `agentLastSeen`, rate-limit exempt, 2 missed
  beats → reconnect), plus a §5 limits row. Existing `ping`/`pong` rows kept.
- `AGENTS.md` — one M7.3 entry recording the invariant.
- Tests: `plugin/tests/test_m73.py` (A blackhole recovery, A′ disabled-beat
  control, A″ ping-answered/hb-not masking probe, B healthy, C 4000 fatal,
  D wrong-id ack), `tests/repro_m73.py` (old vs fixed vs control against the
  same blackhole relay, table output).

## Rollout order (mandatory)

**relay-cf MUST be deployed before the plugin is reinstalled/restarted.**

An old relay broadcasts an unrecognised `hb` to every client and never acks it.
The fixed plugin would then accumulate misses and reconnect every ~22–37 s —
a reconnect loop that looks worse than the bug it fixes, plus `hb` frames
leaking into browsers. relay-node is already fixed in the same commit, so local
e2e runs are safe either way.

Order:

1. `cd relay-cf && npx wrangler deploy`, then check `GET /health` still
   answers (the DO code changed; a bad deploy would take the whole channel
   down, not just the heartbeat).
2. Rebuild and reinstall the plugin ZIP on the hosted agent, then platform
   Restart.
3. Soak: confirm `webchannel.log` stays quiet (no `hb_miss`, no `phase_end`)
   while chats flow, and that a deliberate relay restart produces
   `hb_miss` → `phase_end` → `close` → `reconnect` → `hello`.
