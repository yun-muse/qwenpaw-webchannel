# M34 — 全量备份导出（SPA-only，一键打包全部会话）

背景：M25 已有「导出全部」——逐个会话下载多个 .md。成熟产品的备份应该是**一个文件带走全部**：用户换设备、做存档、或哪天托管环境出问题时，一份完整备份比几十个散文件可靠得多。本任务在不改插件的前提下（SPA-only）把备份做成单文件打包。

## 现状先核对

- M25 批量导出的实现（`spa/src/lib/bulkExport.ts`）：顺序逐会话走既有 export 帧、进度/取消/失败核算、上限 100；导出口径（当前 QwenPaw 历史/上下文视图）与单会话导出一致。
- 单会话导出的 Markdown 格式（M20 v2 头：智能体/模型/导出时间/消息条数/导出口径 + per-turn 用量脚注）。

## 实现要求

- 新增「备份全部会话」动作（放在导出全部附近，文案区分清楚：导出全部=多个 .md 散下；备份=单个打包文件）：
  - 产物为**单个 .zip**：内含每会话一个 .md（复用现有导出内容，一字不改）+ 一个 `index.md`（备份时间、会话清单：标题/消息数/导出状态，会话文件名链接）+ `backup.json`（机器可读清单：生成时间、SPA 构建号、每会话 id/标题/文件名/消息数/状态，失败项带原因）；
  - ZIP 生成必须在浏览器端完成且**不引重型依赖**：优先评估原生实现（store-only 无压缩的 ZIP 格式可手写，仓库已有 CRC/SHA 工具代码可复用思路）；若手写不可行，报告论证后才许引微型库并报体积增量；
  - 流式/分片写入考量：会话多、总体积大时不许把全部内容先拼成一个巨型字符串再打包——按会话逐个写入 ZIP 结构，最终 Blob 组装；给出内存口径的说明；
  - 进度/取消/失败核算沿用 M25 面板与口径：取消时已完成的计数清楚，失败会话进 index 与 backup.json 的失败清单，**不许静默丢弃**；100 会话上限沿用并在 UI 注明；
  - 大小护栏：单会话导出本身有 10MB 上限（既有），备份总大小超 200MB 时给出明确提示再继续（不许无声失败或浏览器崩溃装没事）。
- 文件名：`webchannel-backup-YYYYMMDD-HHmm.zip`（本地时间），会话文件名沿用现有导出的标题清洗规则，注意重名去重（M25 已处理过类似问题，复用）。

## 测试

- vitest：ZIP 结构生成（中央目录可解析、用现成 zip 解析校验条目与内容一致）、index/backup.json 内容、重名去重、失败核算；
- Playwright（mock agent，多会话）：跑完整备份→下载→解开校验 index 与每个 .md 与单会话导出一致；取消路径校验。
- 既有套件全绿并报数。纯 SPA 改动，不许动插件与协议。
- 报告写 `docs/m34-report.md`：ZIP 实现选型与体积/内存口径、与 M25 的关系、测试结果。
