# M36 — 数学公式渲染（懒加载，不许拖慢首屏）

背景：agent 的回复经常带 LaTeX 公式（$...$、$$...$$），现在大概率是原文裸奔。成熟产品都渲染公式。本任务补上，但**体积纪律第一**：公式库必须懒加载，首屏 JS 不许因此变胖。

## 探查任务

1. 现有 markdown 管线（marked 或其他）在代码块/行内代码里对 `$` 的处理、扩展点在哪；流式渲染的分块结构（M32 的冻结头+活尾巴）与公式渲染的衔接点。引用文件+行号。
2. 选型对比（写进报告）：KaTeX（+auto-render 思路，自行实现定界符扫描也可）vs MathJax。比较：gzip 体积、渲染速度、与现有管线集成方式、字体文件如何托管（自托管 vs CDN——本项目部署在 Cloudflare Pages 且用户在国内，**不许依赖海外 CDN**，字体要么随构建自托管、要么用不需要字体的方案并说明代价）。

## 实现要求

- 定界符：`$$...$$` 块级、`$...$` 行内；**代码块与行内代码里的 $ 绝不处理**（转义正确性要有专门用例）；货币写法如 `$5 和 $10` 这类普通文本不许被误吞成公式（给出判定规则，如 $ 后不能紧跟空格、需要成对且同段等，并在用例里覆盖）。
- 流式期间：只在已冻结的完成块上渲染公式，活尾巴保持纯文本（与 M32 结构一致），流结束整条消息落定后公式完整呈现；半截公式（定界符未闭合）不许抛错刷屏，降级为原文。
- 懒加载：公式库用 dynamic import 按需加载（消息里出现定界符才触发），报告给出首屏 bundle 前后对比与懒加载 chunk 体积。字体自托管方案落在构建产物里并验证线上路径可达（相对路径与 SW 缓存策略要兼容：字体进 SW 预缓存还是运行时缓存，给出选择与理由）。
- 深/浅色可读；宽公式在 390px 手机上横向滚动不撑破布局；公式可长按/点击复制 LaTeX 源码是加分项，能简单做就做，不能就跳过并说明。

## 测试

- vitest：定界符扫描/判定纯逻辑（成对、代码豁免、货币误判、未闭合降级）。
- Playwright（mock）：含块级+行内公式的历史消息渲染出公式（断言 KaTeX DOM 出现且无原文 `$$` 残留）；流式中公式落定；代码块里的 `$x$` 保持原样。
- 既有套件全绿并报数。报告 `docs/m36-report.md`：选型对比、体积账、判定规则、测试结果。
